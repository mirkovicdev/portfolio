## Section 0: The Quant Task and the Objects

Portfolio optimization converts assumptions about asset returns into concrete portfolio weights. The inputs are statistical estimates. The output is a vector of weights that tells you exactly how much capital to allocate to each asset.

### The Mathematical Objects

**Expected return vector** $\mu \in \mathbb{R}^n$: Each entry $\mu_i$ is your estimate of the expected return for asset $i$.

**Covariance matrix** $\Sigma \in \mathbb{R}^{n \times n}$: Entry $\Sigma_{ij}$ captures the covariance between assets $i$ and $j$. The diagonal $\Sigma_{ii}$ is the variance of asset $i$.

**Weight vector** $w \in \mathbb{R}^n$: Entry $w_i$ is the fraction of your portfolio allocated to asset $i$.

### Portfolio Return and Risk

Given weights $w$, the portfolio's expected return is:

$$\mu_p = w^\top \mu = \sum_{i=1}^n w_i \mu_i$$

The portfolio variance is:

$$\sigma_p^2 = w^\top \Sigma w = \sum_{i=1}^n \sum_{j=1}^n w_i w_j \Sigma_{ij}$$

These two formulas are the foundation of everything that follows.

### What You Just Built

You've created the **fundamental data structures for portfolio optimization**. Here's what each piece does:

**Covariance matrix validation** (`validate_covariance()`): Checks three critical properties—symmetry, square shape, and positive semi-definiteness. A matrix failing any check would produce meaningless portfolio weights. This validation prevents garbage-in-garbage-out.

**Expected returns vector** (`mu`): A 1D array where each entry is your best estimate of an asset's future return. In practice, these come from factor models, analyst forecasts, or historical averages. The vector format lets you compute portfolio return as a simple dot product: $\mu_p = w^\top \mu$.

**Covariance matrix** (`Sigma`): The heart of portfolio risk. Each off-diagonal entry captures how two assets move together. You built it from correlations and volatilities using $\Sigma = D \cdot \text{Corr} \cdot D$ where $D$ is the diagonal volatility matrix. This decomposition is standard practice—it's easier to estimate correlations and volatilities separately than to estimate covariances directly.

**Portfolio metrics** (`portfolio_return()`, `portfolio_variance()`): These two functions compute everything you need to know about a portfolio. Given any weight vector, you can immediately assess its expected return and risk. Every optimizer uses these functions internally to evaluate candidate portfolios.

**Why this matters**: These objects are universal. Whether you're building a simple mean-variance optimizer or a complex factor-based risk model, you start with $\mu$, $\Sigma$, and $w$. The formulas $\mu_p = w^\top \mu$ and $\sigma_p^2 = w^\top \Sigma w$ appear in every quantitative finance textbook because they're the foundation of portfolio theory.

## Section 1: Minimum Variance Portfolio

The simplest meaningful portfolio optimization problem: find the weights that minimize risk, without any return target.

### Why Minimum Variance?

This portfolio represents the left-most point on the efficient frontier. It's a risk baseline—no other portfolio achieves lower volatility under the same constraints.

The optimization problem is:

$$\min_w \quad w^\top \Sigma w$$

subject to:
- $\mathbf{1}^\top w = 1$ (budget constraint)
- $w \geq 0$ (long-only)

This is a **convex quadratic program**: minimizing a quadratic function with linear constraints. CVXPY handles it naturally.

### Quick Intro: CVXPY

CVXPY is a Python library for convex optimization. The workflow is:

1. **Define variables:** `w = cp.Variable(n)` creates an optimization variable
2. **Define objective:** `cp.Minimize(...)` or `cp.Maximize(...)`
3. **Define constraints:** A list like `[cp.sum(w) == 1, w >= 0]`
4. **Solve:** Create a `cp.Problem(objective, constraints)` and call `.solve()`

The solver finds the optimal values automatically. You access results via `w.value` and `problem.value`.

Every other portfolio on the frontier achieves higher return but at the cost of higher risk. Understanding this baseline is essential for building the rest of the frontier.

## Section 2: Efficient Frontier via Target Returns

One portfolio is not enough. Different investors have different return requirements. The efficient frontier maps out all optimal risk-return tradeoffs.

### Target Return Portfolios

For each target return $\mu_{\text{target}}$, we solve:

$$\min_w \quad w^\top \Sigma w$$

subject to:
- $w^\top \mu = \mu_{\text{target}}$ (target return)
- $\mathbf{1}^\top w = 1$ (budget)
- $w \geq 0$ (long-only)

By sweeping $\mu_{\text{target}}$ from the minimum achievable return to the maximum, we trace out the efficient frontier.

## Section 3: Efficient Frontier via Risk Aversion

There's another way to build the frontier: instead of fixing a target return, we maximize a risk-adjusted objective.

### Risk Aversion Formulation

$$\max_w \quad \mu^\top w - \lambda \cdot w^\top \Sigma w$$

subject to:
- $\mathbf{1}^\top w = 1$
- $w \geq 0$

Here $\lambda \geq 0$ is the **risk aversion parameter**:
- $\lambda = 0$: Maximize return (ignore risk entirely)
- $\lambda \to \infty$: Minimize variance (ignore return entirely)
- Intermediate $\lambda$: Balance return and risk

This formulation has a practical advantage: instead of specifying a target return (which requires knowing what's achievable), you specify your risk tolerance.

## Section 4: Real-World Portfolio Constraints

In practice, portfolios face constraints beyond budget and long-only. These constraints often shape the portfolio more than the objective function.

### Common Real-World Constraints

**Position limits:** No single asset can exceed a maximum weight.
$$w_i \leq w_{\max} \quad \forall i$$

**Sector exposure:** Total weight in a sector cannot exceed a limit.
$$\sum_{i \in \text{sector}} w_i \leq s_{\max}$$

**Turnover constraint:** Changes from current portfolio are limited.
$$\sum_i |w_i - w_i^{\text{current}}| \leq \tau_{\max}$$

These constraints are all linear (or can be reformulated as linear), so the problem remains convex.

## Section 5: Robustness and Numerical Stability

Estimated covariance matrices are often ill-conditioned. Small estimation errors can cause wild swings in optimal weights. Regularization makes the optimizer behave sensibly.

### The Conditioning Problem

A matrix is ill-conditioned when small input changes cause large output changes. For covariance matrices, this happens when:
- Some eigenvalues are very close to zero
- Assets are highly correlated
- Sample size is small relative to number of assets

The condition number $\kappa(\Sigma) = \lambda_{\max} / \lambda_{\min}$ measures this. Large $\kappa$ means trouble.

### Regularization

Adding a small multiple of the identity matrix improves conditioning:

$$\Sigma_{\text{reg}} = \Sigma + \epsilon I$$

This shrinks eigenvalues toward $\epsilon$, preventing near-zero eigenvalues from causing numerical issues.

Sometimes you want a portfolio with at most $K$ assets. This is operationally useful—fewer positions means lower transaction costs and simpler management.

### The Cardinality Constraint

Mathematically, we want to limit the number of non-zero weights:

$$\|w\|_0 \leq K$$

where $\|w\|_0$ counts non-zero entries (the "zero-norm"). For example, $\|(0.3, 0, 0.7, 0)\|_0 = 2$.

### Why It's Hard

**This constraint is non-convex.** Consider why: if $w_1 = (1, 0, 0)$ and $w_2 = (0, 1, 0)$ both satisfy $\|w\|_0 \leq 1$, their convex combination $(0.5, 0.5, 0)$ has $\|w\|_0 = 2$, violating the constraint.

The feasible set is a union of subspaces—not convex. Standard solvers can't handle this directly.

### Modeling Approaches

Since $\|w\|_0 \leq K$ isn't convex, we need alternative approaches:

**1. Mixed-Integer Programming (MIP)**

Introduce binary variables $z_i \in \{0, 1\}$ indicating whether asset $i$ is held:

$$w_i \leq z_i \cdot w_{\max} \quad \text{(if } z_i = 0 \text{, then } w_i = 0\text{)}$$
$$\sum_i z_i \leq K \quad \text{(at most K assets)}$$

This is exact but computationally expensive for large $n$.

**2. Greedy Heuristic**

A practical approach that works well:

```python
# Step 1: Solve unconstrained problem
w = cp.Variable(n)
objective = cp.Maximize(mu @ w - lambda * cp.quad_form(w, Sigma))
constraints = [cp.sum(w) == 1, w >= 0]
prob = cp.Problem(objective, constraints)
prob.solve()

# Step 2: Keep top K assets by weight
selected = np.argsort(w.value)[-K:]

# Step 3: Re-optimize over only selected assets
mu_sub = mu[selected]
Sigma_sub = Sigma[np.ix_(selected, selected)]

w_sub = cp.Variable(K)
# ... solve again with subset
```

This heuristic is fast and often near-optimal, though not guaranteed to find the global optimum.

### 7.3 Interpreting the Results

The analysis above demonstrates several key insights:

**Asset Characteristics**: Individual assets have Sharpe ratios ranging from 0.3 to 0.5. Tech has the highest return (12%) but also high volatility (25%). Utilities has the lowest return (5%) but also lowest volatility (15%). No single asset dominates—this is typical of real markets.

**Strategy Comparison**: Higher risk aversion (λ) shifts the portfolio toward lower volatility at the cost of lower returns. The aggressive strategy (λ=0.5) maximizes return but takes more risk. The conservative strategy (λ=5.0) minimizes risk. Position limits (25% cap) force diversification, slightly reducing Sharpe but preventing dangerous concentrations.

**Constraint Cost Analysis**: Tighter position limits cost performance. Going from unconstrained to 15-20% cap costs about 5-10% of Sharpe. This is the price of risk management—usually worth paying for robustness.

**The Visualization**: The efficient frontier shows the fundamental risk-return tradeoff. The constrained frontier (green dashed) lies inside the unconstrained frontier (blue solid)—position limits reduce achievable performance. However, the gap is small for reasonable limits (25%). Individual assets sit well below the frontier—diversification creates real value.
